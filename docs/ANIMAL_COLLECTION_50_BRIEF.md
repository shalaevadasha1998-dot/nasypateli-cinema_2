# тз дизайнеру — коллекция из 50 животин

обновлено: 2026-09-30

## задача

нужно нарисовать 50 разных персонажей-животин для «насыпателей в кино».

каждый участник получает одну внешность. номер внешности сохраняется у его животины и используется на большом экране. приложение уже умеет распределять номера 1–50 и автоматически искать соответствующий файл.

движение персонажей делает интерфейс. отдельно анимировать все 50 животных для первого мероприятия не нужно.

## сколько файлов

50 персонажей:

- animal-001
- animal-002
- …
- animal-050

для каждого персонажа желательно отдать:

1. png с прозрачным фоном как мастер-файл;
2. webp с прозрачным фоном для приложения.

обязательный production-файл:

- `animal-001.webp`
- …
- `animal-050.webp`

если webp ещё не загружен, приложение автоматически показывает текущую временную животину и не падает.

## размер

рекомендуемый canvas: 1024×1024 px.

- прозрачный фон;
- персонаж целиком;
- единая линия пола;
- важные детали не ближе 80 px к краю;
- персонаж примерно 75–82% высоты canvas;
- одинаковый визуальный масштаб всей коллекции.

1024×1024 — рабочий стандарт проекта, не физическое ограничение проектора.

## визуальные требования

все 50 должны ощущаться одной коллекцией, но хорошо отличаться друг от друга даже при небольшом размере.

можно различать:

- форму тела;
- пропорции;
- уши;
- хвост;
- глаза;
- шерсть / фактуру;
- рожки;
- конечности;
- позу;
- небольшие характерные детали.

не нужно делать 50 почти одинаковых зайцев с одной изменённой деталью.

силуэт каждого персонажа должен оставаться различимым примерно при 100–150 px на общем экране.

## нельзя

- не вписывать имя животины в изображение;
- не добавлять фон;
- не обрезать уши, лапы, хвост;
- не использовать мелкий текст;
- не делать важные элементы слишком тонкими;
- не добавлять тяжёлые полупрозрачные эффекты вокруг всего персонажа;
- не экспортировать персонажа с огромными пустыми полями относительно остальных.

имя рисует само приложение поверх/под карточкой, поэтому оно остаётся резким на любом проекторе.

## движение

для первого мероприятия нужны статичные прозрачные изображения.

приложение уже делает:

- появление новой животины;
- лёгкое idle-движение;
- масштабирование;
- размещение в сетке;
- подпись имени.

если потом понадобятся настоящие анимации, их лучше делать отдельным вторым этапом.

## как проверить перед сдачей

дизайнерский пакет считается готовым, если:

- есть все 50 webp;
- имена файлов строго animal-001.webp … animal-050.webp;
- прозрачность сохранена;
- персонажи находятся на одной baseline;
- ни один персонаж не обрезан;
- все различаются в уменьшенном размере;
- изображения не содержат имён участников;
- визуальный стиль коллекции единый.

## как файлы подключаются

файлы складываются в:

`web/public/assets/`

никакого изменения кода после загрузки 50 файлов не требуется.

при появлении участника проектор получает его сохранённый номер внешности и пытается открыть соответствующий `animal-XXX.webp`.

если файла нет, включается текущая запасная картинка.
