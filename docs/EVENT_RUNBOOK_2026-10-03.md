## как животина появляется на проекторе

### 1. до входа

у гостя уже должна существовать животина в telegram mini app. имя и стадия живут в таблице creatures.

### 2. чек-ин

администратор получает ссылку чек-ина из админки. гость открывает её через telegram. backend проверяет:
- событие существует и check-in разрешён текущим этапом;
- у пользователя есть подтверждённый билет;
- затем registration переводится в attended;
- начисляется награда за вход, если она предусмотрена программой.

ручной запасной вариант: в списке участников администратор может нажать «отметить пришёл».

### 3. projector узнаёт о новом госте

закрытый projector вызывает screen-bootstrap примерно раз в секунду.

screen-bootstrap:
- выбирает только registrations со status=attended;
- подтягивает creatures этих пользователей;
- не отдаёт человеческое имя, telegram username или user_id;
- создаёт стабильный анонимный screen id через sha-256 от event id + user id;
- отдаёт projector только animal id, animal name, stage, crumbs и growth progress.

### 4. появление на экране

когда show находится в блоке arrival:
- проектор показывает стену животных;
- существующие animal id остаются на своих react keys;
- новый animal id определяется как новый;
- только новая карточка делает entrance animation;
- сверху примерно на 4 секунды появляется плашка «в зал заходит {имя животины}»;
- после этого животина остаётся в общей сетке;
- сетка масштабируется до большого количества участников.

### 5. что будет после arrival

животина продолжает быть идентичностью гостя, но projector переключается между состояниями шоу:
- film_intro — фрагмент фильма;
- one_word_collecting — сбор одного слова;
- one_word_results — стена слов с animal names;
- question_open — вопрос «что будет дальше?»;
- question_results — ответы зала;
- question_reveal — продолжение фильма и правильный ответ;
- assignment_randomizing — рандом животины;
- assignment_winner — animal name победителя и фильм на 7 дней;
- past_review_card — итог прошлой миссии без раскрытия человеческой личности.

## что делает ведущий в день мероприятия

### до гостей

1. открыть админку события.
2. получить ссылку общего экрана.
3. открыть её на ноутбуке, подключённом к projector.
4. открыть «репетиция животин» и проверить:
   - картинка не обрезается;
   - имена читаются с последнего ряда;
   - 12 demo-животин помещаются;
   - entrance animation видна;
   - fullscreen браузера включён.
5. проверить каждый из 3 film packages.
6. проверить 6 фрагментов и 5 вопросов каждого выбранного пакета.
7. проверить звук youtube и direct video.
8. получить check-in link.
9. только после этого переводить вечер в рабочий режим.

### на входе

1. projector остаётся на arrival.
2. гость открывает check-in link.
3. после успешного check-in его животина появляется автоматически, отдельной кнопки на projector не требуется.
4. если не появилась за несколько секунд:
   - проверить registration status;
   - при необходимости «отметить пришёл» вручную;
   - не создавать фейковую животину.

### киношный блок

для каждого фильма:
1. «показать первый фрагмент».
2. «одно слово» — открыть сбор.
3. показать слова.
4. вопрос 1.
5. результаты.
6. reveal-фрагмент.
7. повторить для вопросов 2–5.
8. после 5-го вопроса запустить assignment randomizing.
9. выбрать победившую животину через backend assignment.
10. projector показывает animal name победителя.
11. победитель получает постоянную film mission на 7 дней в mini app.

## видеоисточники

автоматический порядок:
1. fragment;
2. trailer/teaser только если пригодного fragment нет.

подключённые discovery providers:
- youtube;
- internet archive;
- wikimedia commons.

projector умеет:
- youtube через iframe;
- прямые mp4/webm через html video для internet archive / wikimedia commons / direct video.

автоматический resolver выбирает только source с rights_status=allowed.
source с unknown rights остаётся в админском пуле и может быть выбран вручную после проверки.
blocked никогда не используется.

## аварийные сценарии

### projector не обновляется

- обновить страницу projector;
- проверить screen token через новую ссылку из админки;
- проверить интернет;
- не менять production data ради визуальной проверки, использовать demo=animals.

### видео не стартует

- остановить текущий показ;
- открыть source link из preflight;
- выбрать другой ready source;
- для film package переключить фрагмент на youtube или direct video;
- если живого источника нет, не пытаться выдавать dead source за готовый.

### животина не появилась

- проверить, что у гостя есть creature;
- проверить registration=attended;
- сделать ручной check-in из admin participant list;
- projector не должен получать человеческие данные.
